# Workflow 30/10 — ideation lens: decision
Raw report of the investigator agent (English, verbatim). Scripts: `scripts/research/wf30/decision/`.
## Measurements
- Setup: scripts/research/wf30/decision/build.py builds component trees on E9a holdout maps (outputs/colab/unet1024_effb4/probs_val). Levels are 0.1,0.2,...,0.9,0.95,0.98 and there are two families: r0 (plain 8-connected components) and r4 (fragments grouped within radius 4, as in the production post-processing). min_area is 50 at 1024. Every node's IoU against every annotator's GT is exact at 2048, computed by block-summing GT masks to 1024. On one image this matches the pipeline's pycocotools IoU to 0.0 difference (check.py). The machine load average was 120-270, so I stopped the build at 123/213 images. Oracle numbers use 117 images and the learned numbers use 123. On these subsets the baseline (strict hysteresis, configs/post_unet1024_effb4_hyst.json, in-sample) scores PQ 0.4131 / 0.4156, close to the full-val 0.408 cross-tuned.
- Analytic result: with pixel-disjoint predictions, each annotator entry gives TP+0.5FP+0.5FN = 0.5*(n_pred + n_gt). So pooled PQ = sum of matched IoU / (0.5*sum_img A_img*n_pred + 0.5*G). The exact optimum is therefore 'keep instance c iff mean over the image's annotators of its matched IoU (0 if unmatched) > PQ/2 (about 0.21)', and over a component tree it is a max-weight antichain (tree DP) solved exactly with Dinkelbach. This is the 'PQ/2 rule' and also what the existing iou-regressor filter targets.
- ORACLE ceilings (analyze.py, paired bootstrap by image, 2000 resamples, delta vs hyst on 117 images): keep/drop on the hyst instances gives PQ 0.4708, +0.058 [+0.049,+0.067] (FP 532->100, FN 666->695). Tree antichain r0 (level + split + keep) gives 0.5403, +0.127 [+0.115,+0.141]. Tree antichain r4 gives 0.5384, +0.125 [+0.114,+0.138] (TP 975->1134, FN 666->507). Keep/drop at the single level 0.5 gives r4 +0.063 and r0 +0.065.
- ORACLE with coarse level sets (diag2.py, 123 images, r4): {0.5} +0.062; {0.3,0.5,0.7} +0.089; {0.3,0.5,0.7,0.9} +0.102; {0.2,0.5,0.8,0.95} +0.110. A per-image single global threshold that keeps everything at it (diag.py) gives only 0.4410 vs 0.4156 (+0.025), so most of the ceiling is per-component, not per-image.
- Oracle-chosen levels are bimodal (diag.py, r4): 199 nodes at 0.98, 137 at 0.1, and only 41-72 at each middle level. Oracle TPs have mean IoU 0.684 with 19.3% below 0.6; baseline TPs have mean IoU 0.668 with 24.4% below 0.6.
- LEARNED selector, honest version (analyze.py): GBM regressor (sklearn HistGBR, 17 instfilter features + level/tree features) predicts mean matched IoU per node. It is fit 5-fold by image (OOF), followed by the tree DP with threshold tau cross-tuned on image halves x3 like compare.py. Results: r0 0.4109, -0.0047 [-0.016,+0.006]; r4 0.4118, -0.0038 [-0.013,+0.005]; keep/drop on hyst instances 0.4146, -0.0010 [-0.0056,+0.0035] (reproduces ledger R5b -0.002). With coarse level sets (diag2.py): {0.5} +0.0005, {0.3,0.5,0.7} -0.0018, {0.3,0.5,0.7,0.9} +0.0006 [-0.007,+0.008], {0.2,0.5,0.8,0.95} -0.0044. Learned selection gains nothing at any granularity.
- Predictor quality is the bottleneck (diag.py): on 12,393 r4 nodes the OOF R2 is 0.255 and Spearman 0.511, residual sd 0.269. Noise injection into the oracle values (iid Gaussian, best tau in-sample): sd 0.02 -> 0.5346, 0.05 -> 0.5288, 0.10 -> 0.5205, 0.269 -> 0.4587. Even the in-sample, iid-noise version keeps only a third of the ceiling at the current error level, and the real (correlated, out-of-sample) errors give about 0. A learned decision layer needs residual sd around 0.1 (R2 about 0.85), which is implausible when human-vs-human PQ is 0.34.
- Annotator agreement of baseline instances (diag.py, images with A>=2), counted as (A, number of annotators matched): (2,0) 66, (2,1) 55, (2,2) 132, (3,0) 29, (3,1) 40, (3,2) 44, (3,3) 76. With the PQ/2 rule, a single-annotator match is worth about 0.33 when A=2 (keep) and about 0.22 when A=3 (break-even). 'Match the union' and 'maximise expected per-entry PQ' therefore differ on at most about 40 instances whose net value is near 0. No measurable gain is available there.
- Machine note: sklearn HistGBR with default OpenMP threads took 748 s for a 20k x 22 fit under load; OMP_NUM_THREADS=1 took 11 s. Set OMP_NUM_THREADS=1 for any CPU analysis while other agents share the box.

## Ideas

### Do NOT build a learned multi-threshold decision layer on hand-crafted features; record it as a measured negative result (H6 rejected for our maps)
- **mechanism**: The decision layer can only realise its oracle ceiling (+0.06 keep/drop, +0.09..+0.13 with level/split choice) if it can predict each candidate's mean matched IoU. Our OOF predictor has R2 0.26. Because the tree DP takes the maximum over correlated noisy scores, it picks over-estimated nodes (winner's curse), and every learned variant lands at -0.005..+0.001. Writing this down stops a costly branch and keeps the pipeline lean, which judges reward.
- **evidence**: Measured on 117-123 E9a holdout images with exact 2048 IoU and image-level CV: oracle tree r4 +0.125 [+0.114,+0.138]; learned tree r4 -0.004 [-0.013,+0.005]; learned on coarse level sets between -0.004 and +0.001; learned keep/drop -0.001 (matches ledger R5b). Noise simulation: residual sd 0.269 erases most of the ceiling. S15's +0.06 is measured against 'every fixed threshold' with no CI, not against tuned strict hysteresis plus a filter. This is inference: their baseline was weaker than ours.
- **expected_gain_pq**: 0 (saves about 10-20 dev hours and the GPU hours a mask-scoring head would need)
- **gpu_hours**: 0
- **dev_hours**: 1
- **cpu_testable_now**: True
- **test_plan**: Already run. To finish properly, rerun build.py and analyze.py on all 213 images with OMP_NUM_THREADS=1 when the machine is idle (about 25 min with 4 workers). Accept the negative result if the learned tree selector's 95% CI upper bound vs hyst stays below +0.01.
- **risks**: This covers 123/213 images and one feature set. A much stronger predictor (idea 2) could change the conclusion. The oracle ceiling is mostly annotator noise ('IoU lottery'), not recoverable signal, so it is no argument for continuing.

### Cross-model disagreement features for the existing keep/drop filter, using the five holdout maps already on disk (r34, r34_grp, r34_e60, cnxt, effb4)
- **mechanism**: The decision layer fails because per-node IoU prediction is weak (R2 0.26). The one cheap feature family we have not tried is epistemic uncertainty: for each hyst instance (or tree node), its mean and max probability under each of the other four models, the std across models, and each other model's best component overlap at 0.5. Averaging the maps did nothing (E-ens6 -0.001), but disagreement is a different signal: it can flag the FPs that only one model believes. FP is our main gap (FP/TP 0.54 here). Later the five N1 fold maps give the same features out-of-fold.
- **evidence**: Inference, untested. Supporting numbers: the keep/drop oracle shows +0.058 is available in FP removal alone (FP 532->100), and the current features are insufficient (R2 0.255). The ensemble-mean result E-ens6 shows the extra models carry no mean-level information, so disagreement may also be near-useless. S12 (ranjeet258) uses a 3-architecture x 4-fold ensemble plus a LightGBM IoU predictor, but reports no ablation.
- **expected_gain_pq**: +0.000 to +0.010 (prior is low; only worth it because it costs about 2 CPU hours)
- **gpu_hours**: 0
- **dev_hours**: 3
- **cpu_testable_now**: True
- **test_plan**: Control: compare.py base = effb4 hyst + current filter (5-fold refit). Treatment: the same filter with about 8 added disagreement features computed from the four other probs_val dirs, 5-fold refit by image, threshold cross-tuned. Report paired-bootstrap delta on 213 images. Accept if delta >= +0.010 with CI lower bound > 0 and OOF R2 of mean matched IoU rises from 0.26 to >= 0.35. Otherwise drop it. Note that it costs 4x the test-time inference unless the same features come from the 5 N1 folds, which are needed anyway.
- **risks**: At test time the four extra models must run, which adds inference cost and pipeline complexity that judges penalise. The holdout models share the training split, so their errors are correlated and disagreement may be small. The likely outcome is +0.003, below detection.

### Treat the oracle's bimodal level choice as a training-target problem (calibrated extent), not a post-processing problem; evaluate through N1/N3 rather than a new decision layer
- **mechanism**: The tree oracle picks either the 0.98 core (199 nodes) or the 0.1 halo (137 nodes) far more often than mid levels. The best per-object extent sits at very different probability levels, so a single probability map does not encode extent consistently. Soft multi-annotator targets (N1, already running) make the map's iso-contours mean 'fraction of annotators who drew this pixel'. The PQ/2 rule then becomes a threshold that is roughly fixed rather than one that varies per object. The concrete action: when N1 maps arrive, rerun this exact oracle/learned analysis (build.py/analyze.py pointed at the N1 OOF maps). Check whether the gap between the single-level oracle and the tree oracle shrinks, and whether learned selection starts to work.
- **evidence**: Measured: single-level-0.5 oracle +0.062 vs tree oracle +0.125 (r4), so half of the ceiling is extent/split choice. The chosen levels are bimodal (0.98:199, 0.1:137, mid levels 41-72 each). Size-dependent extent (ledger R4c) got +0.005, so one size rule captures little. The link to soft targets is inference.
- **expected_gain_pq**: No new gain claimed beyond N1's own result; the diagnostic costs 0 GPU and about 1 CPU hour
- **gpu_hours**: 0
- **dev_hours**: 1

- **test_plan**: When the N1 fold maps exist, run build.py with PROBS set to each fold's val maps and compare (a) the tree-oracle minus single-level-oracle gap and (b) the learned tree selector's delta vs hyst on the same images. Accept 'extent is now learnable' only if the learned tree selector beats hyst on N1 maps by >= +0.012 with CI lower bound > 0 over the 5 folds pooled. Otherwise keep plain hysteresis.
- **risks**: The oracle's level choice may simply chase annotator-specific outlines (the lottery). Then no map, however calibrated, can let a predictor recover it, and the diagnostic will again return about 0.
